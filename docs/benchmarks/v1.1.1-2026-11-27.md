# YAZA v1.1.1 Benchmark Report · 27 November 2026

> Full raw artifacts, runner scripts, and JSON logs live in [`benchmarks/v1.1.1-2026-11-27/`](https://github.com/yazaprojectstudios/yaza-language).

Measured on **Apple M5 (`macOS 26.5 arm64`, 10 logical CPUs)** with **`YAZA LLVM 1.1.1 -O2`**, **`YazaBase 1.1.1`**, **`Rust 1.99.1`**, **`Go 1.27.3`**, **`Nim 2.2.12`**, **`Node.js v26.0.0`**, **`SQLite 3`**, and **`PostgreSQL 18`**.

## 1. Key Performance Gains (`v1.1.0` → `v1.1.1`)

1. **LLVM Guarded `for_range` Vectorization/SCEV & Read-View `list_count` (`compiler/core_llvm.yz`):**
   - Emits `add nsw i64` induction steps, a runtime-guarded (`first >= 0 && end <= 3000000000 && acc == 0`) provably-safe `add nsw i64` SSA accumulator fast path preserving `@llvm.sadd.with.overflow.i64` traps outside the guard (`4.5B` overflow trapped exit `1`), and `load atomic i64 acquire` active read-view `list_count`.
   - **Core 7-Workload Mean (`-O2`, Fresh Process):** `6.136 ms` → **`5.459 ms`** (**beats Rust 1.99.1 `6.005 ms` & Nim `6.630 ms`**), driven by **Sum 10M integers `4.992 ms` → `2.279 ms`** (**2.19× faster**).
   - **5M Binary Search (`ListView` / `List[Number]`):** **`95.259 ms`** (`ListView`, ahead of C `-O2` `102.696 ms` & Rust noinline `119.362 ms`) and **`325.171 ms`** (`List[Number]`, ahead of Go `1.27.3` `353.291 ms`, down from `340.4 ms` while retaining atomic `acquire` concurrency checks).
2. **Convex & Boundary B+Tree Leaf Predicate Elision (`yazabase/btree_scan_v1.yz`):**
   - Validates first & last tuple headers against convex integer primary-key predicates (`=`, `<`, `<=`, `>`, `>=`, and `AND`) and extends `direct_mode == 1` (`COUNT(*)`) to boundary leaves with strict per-slot fence checks (`!=` and `OR` fall back to exact per-row evaluation).
   - **In-Process Filtered Range `COUNT(*)` (`5,001 / 10k` rows):** `0.398 ms` → **`0.0869 ms`** (**4.58× faster**).
   - **3-Way Warm Queries (`YazaBase` vs `PostgreSQL 18`, 10k rows):** YazaBase sweeps **all 7/7 queries** faster than PostgreSQL 18 — `pk_lookup` (`0.021` vs `0.030 ms`), `full_scan_sum` (`0.171` vs `0.233 ms`), `filtered_count` (`0.089` vs `0.254 ms`), `filtered_count_upper` (`0.091` vs `0.253 ms`), `filtered_count_exclusive_upper` (`0.088` vs `0.252 ms`), `narrow_range_inclusive` (`0.031` vs `0.037 ms`), and `narrow_range_exclusive` (`0.030` vs `0.036 ms`).
3. **Sharded Chunk Recycle Cache, Fused `arena_scope` & TLS Elision (`runtime/src/yaza_runtime_v1.c`):**
   - Added a 64-shard `64 KiB` chunk recycle cache, fused `yaza_rt_v1_scope_enter_inplace` / `yaza_rt_v1_scope_leave`, and pure `_Thread_local` `yaza_rt_v1_is_current_context_arena` elision for `yaza_arena_v1_generation` and short-lived paired List operations (explicit leases retained for iterators and mutable views).
   - **200,000-Scope Soak:** `57.74 ms` → **`38.11 ms`** (`5.25M scopes/s`, **1.52× faster**, beating Node.js `v26` `45.45 ms` & Python `68.64 ms`) at **`5.75 MiB` RSS**.
   - **1M C Runtime Scope Cycles:** `29.57M/s` (`33.82 ns`) → **`37.15M scopes/s`** (`26.92 ns`, **+25.6%**, `1.422 MiB` RSS).
   - **11/11 Security & Sanitizer Gates:** ALL PASS (`ASan+UBSan`, `TSan` 0 races, `VFS`, `JWT/YWT`, `Borrow Checker`).
4. **Fullstack Arena-SSR (`std/web/response.yz`, `std/html.yz`) & Cloud-Native Microservice:**
   - Single-pass `TextList` header formatting + zero-allocation ASCII `html_escape` fast path.
   - **Fullstack Arena-SSR (`c=8`):** Hypermedia Fragment **`66,634 req/s`** (**1.82× Go & 1.71× Node**), Static CSS **`68,673 req/s`** (#1), Full SSR HTML lowest `p50` latency (**`138 µs`**, `p95 343 µs`, `34,651 req/s`) at **`6.70 MiB` RSS** (`247.5 KB` binary).
   - **Cloud-Native Microservice:** Peak RSS reduced **-29.8%** (`12.44 MiB` → **`8.73 MiB`**), **`88,164 req/s`** (`85 µs` `c=8`), **`105,179 req/s`** (`c=32`), **`66,491 req/s`** persistent 10k-row YazaBase lookup (`c=8`).

*(Data Science `86/86` SciPy golden, `YBIF` `2.17×` vs JSON, Loopback API `102k req/s`, and Mobile C ABI `0.167 µs` remain as verified in [`v1.1.0-2026-11-26.md`](v1.1.0-2026-11-26.md).)*
